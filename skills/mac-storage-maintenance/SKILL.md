# Mac 磁盘清理与 SSD 迁移

按用户本次要求确定范围。只问位置、占用或可行性时做只读检查；明确要求清理或迁移时，直接完成已授权且可验证的项目。对唯一数据、备份或仍需使用的运行环境，先查清用途和恢复路径。技能本身不授予删除权限，也不创建自动巡检。

- 查本机位置、缓存回长和各类清理方式，读 [缓存与数据位置](references/storage-map.md)。
- 搬目录、应用或修改默认生成位置，读 [迁移与回退](references/migration.md)。

- 遇到浏览器更新、应用启动或同步故障，读 [实际案例](references/field-notes.md)。

## 一次维护的工作顺序

1. 用 `df -k /System/Volumes/Data`（不存在则查 `/`）记录内置盘可用字节。若涉及 SSD，用 `diskutil info -plist` 验证目标确实挂载、卷身份与预期一致、可写且有足够空间。挂载目录存在本身不能证明磁盘在线。卷不在线时继续可做的本机检查，暂停外置写入。
2. 用 `du -x -k -d 1` 对选定目录逐层查找，默认不跟随链接、不跨卷。结合 `lstat`、解析后路径和设备号区分本机实体、SSD 链接、已断链接、外置卷和云占位。记录权限缺口；把 APFS 共享块、快照、打开但已移除的文件和同步活动纳入解释，目录占用不等同于净释放量。盘点时只输出路径、字节、占用状态等必要信息。
3. 逐项判断归属、是否正在使用、是否能重建、是否存在未同步或唯一副本。优先采用软件原生的清理、位置设置和按需下载。对确认闲置且可重建的缓存，可按授权移除具体项目；对用户文件和应用采用可验证的迁移。目录名含 Cache、Temp 或 Backup 本身不足以判断用途。释放内置盘空间时，删除范围只限解析后确实位于内置盘的已确认项目。执行前重新核对路径、设备号、链接和写入者，防止更新器在盘点后改变目标；只处理列出的具体项目，避免通配符扫整个缓存根目录。对已移除但仍打开的文件，确认占用进程和句柄，待其安全释放后复测。存在冲突、进程占用、受保护路径或状态不明时，先解决该项的具体问题，继续其他可做项目。
4. 验证恢复或新写入行为。对设置进行回读并尽可能在重启应用后检查真实输出；对迁移确认原入口、完整性和实际运行；对删除复测空间与相关功能。需要用户处理系统权限时，保留可回退状态并说明哪一步尚待验证。
5. 记录前后实际可用空间、路径及每项处置、验证范围、仍保留的内容和下一步。跨轮只报告有证据的变化。历史脚本和清单作为证据参考，每次按当前路径、版本、活动状态重新判断。

## 优先检查的回长原因

更新程序重新创建版本目录或把实体应用装回内置盘；启动时未挂载 SSD 导致工具写入本机默认位置；某个项目或资源库单独覆盖默认目录；浏览器新配置档、云文件离线下载或新增模拟器运行环境；原本转移的链接被安装器替换。先确认是谁重新写入，再修正设置或处理单项重复副本。
