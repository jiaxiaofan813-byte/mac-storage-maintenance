# 迁移、验证与回退

## 目录和下载

- 优先改应用自身的输出或存储设置。兼容链接适用于软件实际接受链接、外置卷常驻的情况；容器、云同步根目录、数据库优先保留受支持的位置。
- 查源和目标的实体、链接、相对目标、ACL、权限、扩展属性、云占位、重名和活跃写入者。用 `lsof` 等工具交叉验证；权限或扫描缺口要记录。对下载中、项目写入中或来源不明的对象暂缓切换。缩略图只读映射和目录枚举与写入有不同影响，遇到它们应核对句柄类型，回收空间可能延后。
- 在 SSD 同卷暂存，用 `ditto` 等保留所需元数据及链接。校验目录结构、普通文件 SHA-256、链接目标及必要的权限、ACL、扩展属性。迁移前后的清单要能识别源内容变化。下载目录曾分批搬过时，识别指向同名目标的旧链接，保留目标实体，避免制造指向自身的链接；指向其他归档的有效链接保留。重名不覆盖。移动相对链接前计算新旧解析结果。
- 再次确认源稳定及无写入，改名保留本机回退件，再切换原入口。切换失败立刻恢复原名及必要元数据。macOS 的 Downloads 可能有默认禁止删除 ACL；确认实际阻碍后只处理对应 ACL，给迁移后的目录保留隐私和保护，避免全局或递归放宽权限。
- 通过旧入口写一个唯一小文件，验证落在目标卷、读取一致并删除测试件。通过 Finder 或相关软件实测入口；浏览器另存位置和旧书签仍需单独验证。复核原清单和回退件在切换期间无新写入，确认新路径可用后再处理已验证的本机重复件。

## 应用

- 查是否为系统组件、带后台驱动的应用、更新器管理的程序或 App Store 应用。必要时检查安装器对外置卷的支持。预先验证原签名，保留原路径、版本与安装来源。复制后核对签名和完整性；`codesign --verify --deep --strict` 与系统评估的结果分别记录。
- 发生签名问题时先确定是扩展属性、额外生成文件，还是签名资源变化。只针对已确认的问题，在暂存副本上做最小且可追溯的修复并重新验证。找不到可靠原因时用官方安装包获得干净副本。不要用重新签名、取消隔离或关闭安全检查掩盖问题。
- 用正常入口启动并检查实际可执行文件位置、基本功能、原用户资料和重启。应用更新器可查时验证登记位置；未来更新仍可能重新安装到内置盘。图形启动卡住时检查用户可见权限提示、应用日志和临时目录。等待系统权限或功能验证时保留本机回退件；后台能运行不足以证明图形界面可用。
- Xcode 迁移分三层核对：应用本体、`xcode-select -p` 指向的默认 Developer 目录、构建和模拟器数据。使用默认工具链做小型编译和执行，列出所需模拟器；应用能打开并不能证明默认编译器已切换。

## 防止新的本机大文件

- 按软件优先级改位置：资源库或项目设置、应用偏好、工具持久设置、shell 子进程环境。检查被项目参数覆盖的配置，以及 GUI 与 shell 的不同。
- 对新任务和项目直接使用 SSD 上的输出目录。SSD 断开时让依赖外置盘的任务暂停；对现有 shell 配置是否回退到本机，按实测描述。不要将系统临时区、交换文件或系统管理缓存整体重定向。
- 查默认下载、构建、渲染和缓存时，以实际输出的设备号为准。终端 `TMPDIR` 成功不代表 Foundation 或 GUI 采用相同路径。

## 恢复

退出相关进程，核对内置盘空间和 SSD 上迁移后新增文件。若回退件已过时，先从 SSD 复制当前内容到本机暂存并验证，避免用旧副本覆盖新数据。替换链接前保存可逆入口，恢复对应设置、权限和必要注册，再用原入口验证。回退时先区分删除链接与删除链接的目标。
